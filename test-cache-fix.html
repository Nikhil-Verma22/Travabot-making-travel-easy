🐛 Cache Bug Fix - Explore Page Not Updating

Fixed the issue where Explore page showed stale data when trip details changed

❌ Problem: Stale Cache Data
Issue #1: Incorrect Dependencies

The usePOIs hook had wrong dependencies causing stale closures:

useEffect(() => { // Cache check logic }, [lat, lng, radius, cityName, includeHotels, fetchTrigger, forceRefresh, cachedData, isCacheValid, setCachedData]); // ❌ These dependencies caused stale closures!
Issue #2: Duplicate POI IDs

Multiple cities used the same IDs (e.g., id: '1', '2'), causing React confusion:

'jaipur': { attractions: [{ id: '1', ... }] }, 'delhi': { attractions: [{ id: '1', ... }] } // ❌ Duplicate IDs across cities!
Issue #3: Silent Cache Clearing

No logging to confirm cache was being cleared, making debugging difficult.

✅ Solutions Implemented
Fix #1: Corrected Dependencies
useEffect(() => { const cacheIsValid = isCacheValid(); // Call inside, not as dependency // ... cache check logic }, [lat, lng, cityName, includeHotels, fetchTrigger, forceRefresh]); // ✅ Removed cachedData, isCacheValid, setCachedData, radius
Fix #2: Unique POI IDs
'jaipur': { attractions: [{ id: 'jpr-1', ... }] }, 'delhi': { attractions: [{ id: 'del-1', ... }] } // ✅ Unique IDs with city prefix!
Fix #3: Debug Logging
if (currentHash && newHash !== currentHash) { console.log('🗑️ Clearing cache due to trip change'); clearCache(); } // ✅ Easy to debug in browser console!
Fix #4: Expanded POI Database

Added comprehensive data for 6 cities: Jaipur, Udaipur, Delhi, Mumbai, Bangalore, Goa

🔄 How It Works Now
1. User changes city on Home page
2. TripContext.setTrip() called
3. generateTripHash() creates new hash
4. Hash comparison detects change
5. clearCache() removes cached data
6. Explore page's usePOIs hook detects city change
7. useEffect re-runs (lat/lng/cityName changed)
8. Cache validation fails (cache was cleared)
9. Fresh data fetched for new city
10. New data displayed on Explore page
